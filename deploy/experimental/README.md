# Экспериментальная установка Wi-Fi — не устанавливать автоматически

Здесь находятся шаблоны будущей установки, а не команда обновления работающей
платы. Старые Netplan-профили, дополнительные systemd overrides и DHCP wlan0
должны быть проверены при согласованной миграции по Ethernet. До этого не
копировать шаблоны в /etc и не включать службы.

Подготовлены:

| Компонент | Будущий путь |
| --- | --- |
| Подготовка WPA2/CCMP перед запуском | /opt/encoder/bin/encoder-wifi-policy-guard |
| Независимый наблюдатель отката | /opt/encoder/bin/encoder-wifi-recovery-supervisor |
| Проверка области Netplan | /opt/encoder/libexec/netplan_preflight.py |
| Сохранённый профиль | /etc/netplan/90-encoder-wifi.yaml |
| Временная строгая конфигурация | /run/encoder-wifi-policy/wpa-wlan0.conf |
| Журнал и локальный сокет наблюдателя | /var/lib/encoder-wifi-recovery |

Бинарные файлы, скрипт и родительские каталоги должны контролироваться root.
Журнал и временная конфигурация находятся в каталогах 0700, файлы ключей — 0600.
Журнал намеренно не размещается внутри доступного обычному серверу /var/lib/encoder.

Шаблон drop-in сохраняет зависимости исходной службы Netplan и меняет её запуск:
сначала выполняется guard, затем wpa_supplicant читает подготовленный файл.
Reload отключён: обновление должно идти через restart с повторной подготовкой.
Команда и выбор драйвера сверены с
[генератором службы Netplan](https://github.com/canonical/netplan/blob/main/src/gen-networkd.c).

WifiLinuxPlatform содержит фиксированные действия только для
netplan-wpa-wlan0.service. Он не выполняет netplan apply и не перенастраивает
Ethernet. Проверка собственного drop-in не заменяет проверку эффективной службы:
другие overrides, маскировка службы и локальные изменения проверяются до установки.
Адрес Ethernet передаёт доверенный helper, не клиент; проверка того, что
администратор действительно использует резервное подключение, остаётся задачей API.

Ограничение времени systemctl не отменяет уже принятую systemd задачу. Поэтому
ошибка оставляет журнал незавершённым, а откат повторяется. Успешный restart сам
по себе не подтверждает Wi-Fi: отдельно проверяются целевая сеть и её IPv4.

Проверки CI: подготовка/восстановление временного файла, отказ от ослабленной
политики, фиксированные команды на имитаторе и systemd-analyze verify с настоящей
сгенерированной службой Netplan в частном временном корне. Эти проверки не
запускают Wi-Fi и не заменяют загрузку реальной платы. API/helper IPC и окно
подключения пока не связаны с новым адаптером.
