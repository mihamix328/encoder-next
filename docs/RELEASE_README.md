# encoder

Клиент-серверное приложение для шифрования файлов. Windows-клиент отправляет
операции отдельному Linux-серверу по TLS; админ-панель управляет пользователями
и показывает состояние устройства.

## Быстрый запуск

1. Распакуйте готовый архив обычного клиента или админ-панели полностью.
2. Получите у администратора адрес сервера и его публичный сертификат.
3. Откройте `encoder-client.exe`, укажите порт 7443 и свою учётную запись.
4. Для админ-панели используется `encoder-admin.exe`, порт 7444 и отдельный токен.

Ethernet достаточен: Wi-Fi и доступ в Интернет для шифрования не требуются.
ПК и сервер должны иметь доступ друг к другу. Прямой кабель требует настройки
адресов одной подсети; адреса по умолчанию не назначаются клиентом автоматически.
Проверка сертификата должна оставаться включённой.

**Перед шифрованием сделайте копию файла: клиент заменяет выбранный файл
зашифрованным контейнером.** Сначала проверьте полный цикл на несекретной копии.
При серверном хранении ключей нужны резервные копии всей базы сервера.

## Статус выпуска

Это кандидат на выпуск, не заявление о сертификации защиты. Основное шифрование
проверено на устройстве, в том числе после перезагрузки. Финальная проверка
последнего ZIP на чистом втором ПК ещё требуется.
Смена Wi-Fi экспериментальна: не включена в стандартной конфигурации.
Успешное подключение ко второй сети с подтверждением и возврат по истечении
срока подтверждения ещё требуют аппаратной приёмки.

`client`, `admin`, `server` и `common` содержат исходники. Готовые ZIP публикуются
отдельно в Releases, а не в каталоге build репозитория. Реальные сертификаты,
токены, базы, пароли и приватные ключи не входят в публичный комплект.
Лицензионные уведомления библиотек сохраняются в каталогах licenses ZIP-пакетов.
Старые gost.c/decr.c оставлены для диагностики совместимости, не для установки
в качестве рабочего шифратора. Нативный ГОСТ требует libakrypt и отдельного
параметра сборки; без него сервер отказывает в ГОСТ-операциях.
