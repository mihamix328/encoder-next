## Найденные препятствия безопасному переносу

1. Сертификат старой установки: CN=orangepi3b, без Subject Alternative Name.
   Действителен 07.09.2026–07.09.2027, но не подходит для строгой проверки IP.
   Нужен новый сертификат с согласованными адресами и обновление доверия на ПК.
2. Пути обеих ГОСТ-конфигураций ведут в отсутствующий /home/server/Cipheator.
3. Старые gost.c/decr.c используют только Кузнечик, а не отдельную Магму;
   ручной CBC не соответствует всем режимам, предлагаемым клиентом.
4. Диагностический round trip на искусственных данных: длины 0,1,15,17,31
   проходят; длины 16,32,64 с последним байтом 0x01 не восстанавливаются точно.
   Шифратор не добавляет полный блок padding, а дешифратор удаляет данные,
   похожие на padding. Нельзя просто установить эти бинарники как готовые.
5. В старом исходнике используется LCG для ключа/IV и печать ключа в stdout.
   Эти программы не одобрены для новой рабочей установки.

server/tests/legacy_gost_check.py воспроизводит проблему только на временных
данных, подавляя вывод старых программ (он содержит ключи). Это диагностический
тест, его не добавляли в успешный набор CTest. Старые файлы не удалены.

Перед переключением исправить/заменить ГОСТ-реализацию, определить совместимость
старых контейнеров и проверить новые сертификаты. Не терять старые ключи и базу.

шифротекста по доверенной исходной контрольной сумме, без угадывания padding.
