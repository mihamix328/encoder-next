# Подключение Wi-Fi: разработка без изменения платы

## Реализованный этап

WifiProfile проверяет SSID (1–32 байта, без управляющих символов) и пароль
WPA2-Personal: 8–63 печатных ASCII-символа либо 64 шестнадцатеричных цифры PSK.
Пробелы не обрезаются. SSID кодируется в hex, а не вставляется в shell/YAML-команды.
Правила passphrase описаны в [wpa_supplicant](https://w1.fi/wpa_supplicant/devel/structwpa__ssid.html).
WPA3-only, Enterprise, открытые сети и двоичные SSID с управляющими символами
пока не поддерживаются; автоматического ослабления защиты не предусмотрено.

Из passphrase получается 32-байтный PSK (PBKDF2-HMAC-SHA1, 4096 итераций, SSID
как соль). Это предписанный WPA2 формат, не выбор алгоритма хранения паролей
пользователей encoder. PSK хранится в некопируемом SecureBuffer и очищается при
освобождении. PSK даёт доступ к сети и остаётся секретом. Factory принимает
string_view: вызывающая сторона обязана отдельно очистить свой исходный пароль.
Нет записи пароля/PSK на диск, в журналы или аргументы процессов.

WifiChange — однопоточная, одноразовая логика транзакции над интерфейсом backend:

1. Проверить подготовленный профиль и резервный Ethernet-доступ.
2. Создать случайный одноразовый билет подтверждения (32 случайных байта).
3. Подготовить восстановление ДО активации нового подключения.
4. Подождать готовности целевой сети с пригодным IP; ассоциации недостаточно.
5. Получить явное подтверждение с правильным билетом не позднее 90 секунд
   от начала операции. Повторно проверить состояние сети перед сохранением.
6. При ошибке, отмене, потере Ethernet или отсутствии подтверждения вызвать откат.
   Если откат не удался — RecoveryRequired, а не сообщение об успешном возврате.

Билет сравнивается constant-time при совпадении длины, очищается после завершения
и не должен журналироваться. Он НЕ заменяет административный токен и TLS.
Объект не копируется; backend должен жить дольше него. Адаптер обязан сериализовать
операции межпроцессной блокировкой, а вызывающий цикл — регулярно вызывать tick().

## Что эта реализация пока НЕ делает

Это проверяемое ядро, а не готовая функция переключения платы. Оно не подключено
к API, GUI или реальному сокету supplicant, не пишет Netplan и не запускает службы.
Поэтому на рабочей плате нет новой возможности менять сеть.

Деструктор делает best-effort откат ожидающей транзакции при обычном уничтожении.
Это НЕ защита от SIGKILL, отключения питания или аварии процесса. Реальный backend
должен до activate() сохранить журнал восстановления и запустить независимый
watchdog. При перезагрузке также должен разбираться незавершённый журнал.
Без этого контракт prepare() не выполнен и реализацию нельзя подключать к API.

## Следующие шаги по порядку

- Подключить реализованный журнал и шаг независимого восстановления к будущей
  root-службе/watchdog; служба ещё не установлена и не управляет Netplan.
- Адаптер Netplan/systemd-networkd: сохранять прежнюю конфигурацию, менять только
  wlan0, не затрагивать end1, фиксировать новую сеть только после подтверждения.
- Ограниченный локальный протокол begin/status/confirm/cancel, без shell и без
  произвольных путей; административный API через TLS с функцией, выключенной по умолчанию.
- Диалог SSID/пароля, статус, обратный отсчёт и подтверждение, понятные ошибки.
- Возвращаемый новый IP и повторное обнаружение платы с проверкой идентичности.
- Аппаратные проверки только когда пользователь решит к ним вернуться.

## Автоматическая проверка

CTest wifi-change использует исключительно Fake-backend. Проверяет известный
вектор PSK, ограничения полей, защиту от повторного использования профиля,
порядок prepare/activate/commit, отказ неверному билету, потерю готовности,
таймаут (включая точную границу), отмену, ошибки prepare/activate/commit,
ошибку восстановления и откат при закрытии владельца. Сетевые команды не вызываются.

## Журнал восстановления и независимый процесс — 17 сентября 2026

Linux-модуль WifiJournal хранит одну транзакцию в выделенном закрытом каталоге.
Каталог — 0700 и принадлежит effective uid (в рабочей установке потребуется root).
В тестах используется encoder-diag и новый временный каталог, без root.
Доверенная цепочка родительских каталогов — обязанность установщика; клиент
не должен передавать пути. Leaf-ссылки, чужой владелец, общие права и hardlink
для lock/journal отвергаются. Блокировка flock не ждёт занятого журнала.

Формат ограничен: версия, фаза Pending/Committed/Restored, ID транзакции,
boot ID, срок CLOCK_BOOTTIME, признак существовавшего файла, непрозрачная копия
прежней конфигурации до 64 КиБ и SHA-256. Из журнала не читаются команды или пути.
SHA-256 обнаруживает повреждения, а не защищает от злоумышленника с root.
Копия может содержать старые сетевые секреты: файл 0600, рабочие буферы очищаемые.
При разрешении транзакции новая запись больше не содержит резервную копию;
физическое стирание старых блоков файловой системы не гарантируется.

Запись: новый файл O_EXCL/NOFOLLOW → полная запись → fsync файла → renameat
→ fsync каталога. Незавершённые .journal-* не считаются действующим журналом;
после аварии могут остаться закрытые временные файлы (автоочистка ещё не добавлена).
Незавершённая транзакция не перезаписывается следующим begin(). Неопределённая
durability или повреждение — ошибка, а не разрешение продолжить переключение.

Срок не зависит от перевода настенных часов. CLOCK_BOOTTIME учитывает сон;
смена boot ID требует немедленного восстановления Pending. Committed не
откатывается после перезагрузки. Операции подтверждения и восстановления
сериализуются одной блокировкой. Её нельзя держать всю 90-секундную сессию:
зависший координатор иначе заблокирует watchdog. Настоящий backend должен
ограничивать время каждого участка под блокировкой.

wifi_recovery_tick — один шаг независимого наблюдателя: открыть журнал, получить
boot ID/время уже под блокировкой, вызвать идемпотентное восстановление по сроку.
При неудаче сохраняется Pending, чтобы следующий проход повторил попытку.
При аварии между восстановлением и отметкой Restored восстановление повторится,
поэтому адаптер обязан безопасно переносить повтор. До commit адаптер обязан
надёжно сохранить новую конфигурацию; после restore — восстановить и применить старую.
ID транзакции не заменяет секретный билет/административную авторизацию.

CTest wifi-recovery-journal прошёл на ARM64: права, конкурирующий писатель,
целостность, граница срока, имитация смены boot ID, ошибка восстановления,
символьные и жёсткие ссылки, неподходящие права, незавершённый временный файл.
После SIGKILL координатора другой процесс прочитал журнал и восстановил
тестовый файл. Отдельный дочерний наблюдатель также дождался срока и восстановил
файл без вызовов tick() из координатора. Это файловая проверка, не испытание
отключением питания и не восстановление реального Wi-Fi.

Граница готовности: библиотека журнала и шаг наблюдателя готовы для интеграции,
но production watchdog, адаптер Netplan, API подключения и UI ещё не подключены.
На плате не установлены новые службы и не изменены сетевые настройки.

## Файловый слой Netplan — 22 сентября 2026

Добавлен NetplanFiles: запись и восстановление только 90-encoder-wifi.yaml
в доверенном каталоге. Другие файлы не перезаписываются. Для уже существующего
файла обязательны владелец helper, закрытые права, отсутствие символьных/жёстких
ссылок и маркер `# encoder managed wifi v1`. Чужое содержимое не перезаписывается
и не удаляется, даже если имя совпало. Размер ограничен 64 КиБ; буферы очищаемые.
Путь каталога должен задаваться привилегированной конфигурацией, не запросом клиента.

Сохраняются исходные байты и признак отсутствовавшего файла. Замена выполняется
через отдельный файл 0600, fsync, rename и fsync каталога; восстановление отсутствия
удаляет только собственный помеченный файл. Повторное восстановление допустимо.
Маркер не является проверкой синтаксиса YAML или доказательством того, что внутри
описан только wlan0. Генератор и проверка области изменений ещё требуются.

wifi_managed_recovery_tick связывает журнал с файловым слоем и отдельным callback
применения настроек. Restored записывается только после успешного восстановления
файла И применения. Если применение не удалось, Pending остаётся для повторной
попытки. Сетевой callback пока не реализован: реальные команды не вызываются.

Подготовлен Linux-тест netplan-files: точное восстановление, отсутствие исходного
файла, чужие данные, ссылки, права, лимит размера, сохранение соседнего Ethernet-файла
и повтор после ошибки применения. В этой контрольной точке тест НЕ выполнен:
диагностический SSH к плате недоступен (таймаут/сброс), WSL на ПК не установлен.
Код не установлен на плату. Это ещё не готовое переключение сети и не готовая
production-служба: следующий шаг — Linux-проверка, безопасный генератор профиля,
адаптер применения только wlan0 и интеграция с watchdog.

## Проверка текстовых SSID — 22 сентября 2026

WifiProfile теперь принимает только корректный UTF-8 без управляющих символов
и разделителей строк U+2028/U+2029. Некорректные последовательности, суррогаты,
избыточные кодировки и значения выше U+10FFFF отклоняются до вычисления PSK.
Кириллица и emoji сохраняются побайтно, без обрезки пробелов и нормализации:
изменение имени изменило бы также соль ключа. Лимит остаётся 32 байта,
а не 32 символа. Сети с нетекстовыми SSID пока не поддерживаются.

Сборка Windows и все 6 локальных CTest прошли, включая новые проверки UTF-8,
32-байтовой границы и сохранения имени. Проверки не меняют настройки платы.
Генератор YAML ещё не реализован: перед интеграцией требуется проверить,
как установленная версия Netplan выражает политику WPA2 без отката на WPA1,
и обработать существующие сторонние объявления wlan0 без их перезаписи.

## Генератор конфигураций (черновики, не применение) — 22 сентября 2026

`make_wifi_config_draft` формирует в памяти два очищаемых буфера: YAML для
Netplan и строгую конфигурацию wpa_supplicant. В YAML присутствует только wlan0,
renderer задан на уровне интерфейса, IPv4 получается по DHCP. SSID всегда
заключён в кавычки с экранированием; пробелы и UTF-8 не изменяются. Во втором
формате SSID представлен hex-байтами, политика — RSN / WPA-PSK / CCMP.
PSK записывается непосредственно в SecureBuffer без промежуточной строки;
это всё равно секрет, не шифрование и не безопасный для публикации хеш.
Перемещённый/пустой профиль отклоняется, входной пароль не сохраняется в черновике.

ВАЖНО: эти два документа НЕ образуют готовый способ установки. Netplan YAML
сам по себе не гарантирует WPA2-only: проверенный генератор Canonical не задаёт
`proto=RSN` для `psk`, а `psk-sha256` также допускает WPA-PSK. Нельзя просто
записать YAML и вызвать netplan apply. Адаптер должен обеспечить применение
строгого профиля при запуске и перезагрузке, совместимость с установленными
Netplan/supplicant и точное сохранение SSID в их выходных файлах. Генератор
никаких файлов не пишет, служб не запускает и к рабочему серверу не подключён.

Проверки: 7 Windows CTest и независимый разбор YAML через PyYAML 6.0.2 прошли.
Проверены точное дерево только wlan0, кавычки, обратный слеш, спецсимволы,
кириллица/emoji, известный PSK и отказ перемещённому профилю. Дополнительный тест:
`python common/tests/wifi_config_yaml_check.py <путь-к-encoder-wifi-config-tests>`.
Он требует PyYAML и использует только встроенные публичные фиктивные данные.
Настоящие Netplan и supplicant этой проверкой не запускались.

Источники для политики: [генератор Canonical Netplan](https://github.com/canonical/netplan/blob/main/src/networkd.c),
[формат wpa_supplicant в исходниках AOSP](https://android.googlesource.com/platform/external/wpa_supplicant_8/+/refs/heads/main/wpa_supplicant/wpa_supplicant.conf).

## Готовность целевой сети — 22 сентября 2026

Добавлен `assess_wifi_link`: полный ограниченный STATUS, без повторов важных
полей, должен показывать COMPLETED, точное имя целевой сети, WPA2-PSK и CCMP
для обоих шифров. SSID сравнивается побайтно после декодирования escape-формата
supplicant; пробелы не обрезаются. IPv4 должен быть корректным unicast, не
loopback/link-local, и присутствовать в актуальном списке адресов wlan0.
Старая сеть или ожидание DHCP остаются Pending; повреждённый ответ и неподходящая
защита дают Failed. IPv6-only пока не поддерживается. Это не проверка Интернета.

Linux-библиотека `encoder_wifi_probe` читает свежий STATUS из фиксированного
/run/wpa_supplicant/wlan0 и IPv4 только включённого/running wlan0 через getifaddrs.
Она НЕ подключена к основному TLS-серверу и не предоставляет ему привилегий.
Для тестов доступна отдельная точка подстановки сокета и чтения адресов;
клиентские пути туда передавать запрещено. Снимок интерфейса остаётся наблюдением
в момент запроса, не гарантией непрерывной связи. Перед commit адаптер обязан
повторить проверку, отдельно подтвердить Ethernet, watchdog и билет пользователя.

Все 8 Windows CTest прошли. Для Linux подготовлен тест настоящего Unix-сокета
с имитатором supplicant: только STATUS, без SCAN/SET_NETWORK и без радио.
Проверяются готовность, отсутствие IP, ошибки/исключения чтения адресов,
переходное состояние и недоступный сокет. Linux-результат проверяется в CI.

Свежий пробник и все 12 Linux CTest подтверждены запуском 35728997310 (96d891c).
Дополнительно связаны тесты готовности и WifiChange: старая сеть, отсутствие
локального IP и понижение защиты не позволяют подтвердить операцию. Случайные
байты билета теперь находятся в RAII-буфере, очищаемом также при исключении.
wifi_managed_cancel связывает явную отмену с тем же восстановлением файла и
повторным применением, что использует наблюдатель. Добавлены проверки отказа
чужому ID, ошибки применения, точного восстановления и повторной отмены.

## Read-only проверка конфликтов Netplan

`server/tools/netplan_preflight.py` (Linux, PyYAML) проверяет только пригодность
текущих файлов для последующего изолированного staging. Никаких команд применения,
записи конфигурации, подключения или миграции нет. Это пока отдельный инструмент,
не часть привилегированной службы. Root-каталог — доверенный аргумент оператора,
не параметр сетевого запроса; его предки должны быть доверенными.

Проверяются каталоги lib/netplan, etc/netplan, run/netplan, владельцы и права,
обычные файлы без символьных/жёстких ссылок, ограничения размера и сложности YAML.
Повторы ключей, aliases/merge, неподдержанные типы и несколько YAML-документов
отклоняются. Ошибки парсера не выводятся, чтобы не раскрыть строки с паролем.
Консервативно проверяются и перекрытые по имени файлы. Скрытые .yaml игнорируются;
эта семантика отдельно проверяется настоящим Netplan во временном каталоге.

Автоматически допускается только простая схема end1 + управляемый wlan0.
Чужие Wi-Fi-определения, другие типы интерфейсов, match/set-name, другой renderer
и управляемое имя вне etc/netplan требуют ручной миграции. Управляемый файл
должен содержать строго одну точку доступа wlan0 и ожидаемые поля генератора.
Это намеренные ограничения первого варианта, не заявление о невалидности
таких конфигураций для Netplan вообще. Unicode noncharacters также отклоняются.

Даже OK НЕ означает разрешение применять: ещё нужны проверка реального Ethernet,
защита от изменения файлов после preflight, сравнение изолированно сгенерированных
выходов, устойчивый WPA2-only, журнал, watchdog и пользовательское подтверждение.
Python-парсер не гарантирует обнуления временных копий в памяти. Будущая служба
должна ограничивать core dump и доступ к процессу; инструмент не выводит ключи.
Добавлены изолированные тесты отказов, сохранности файлов и отсутствия секретов

## Строгое чтение и файловый контракт

`read_wifi_config_draft` читает только точный формат собственного генератора,
не произвольный YAML. Он ограничен 4 КиБ, извлекает SSID/PSK без промежуточной
строковой копии ключа, заново проверяет профиль и сверяет повторную сериализацию.
Нестандартное форматирование, дополнительные поля, комментарии, чужой интерфейс,
другой режим защиты и неполный файл отвергаются без вывода содержимого.
Буфер входного файла содержит секрет: очистка его памяти остаётся обязанностью
вызывающего кода. Сам профиль и повторная сериализация используют SecureBuffer.

NetplanFiles теперь использует этот читатель для существующего файла, кандидата
и резервной копии. Прежней проверки маркера недостаточно; текущий лимит уменьшен
с 64 до 4 КиБ. Это отменяет прежнее ограничение «маркер не проверяет структуру»
именно для управляемого файла. Чужие файлы всё ещё требуют preflight и проверки
гонок; управление сетью остаётся отключённым. Тесты файлового слоя переведены
на настоящие сгенерированные фиктивные профили, добавлены отказы ложному маркеру.

Строгий файловый контракт подтверждён Linux-запуском 35731241802 (a13f851):
12 CTest, 9 preflight-проверок, настоящий Netplan во временном root, YAML и TLS.

## Подтверждение сохранённого кандидата

`wifi_managed_commit` под общей блокировкой проверяет Pending, ID и реальное
время текущей загрузки, затем сравнивает сохранённый файл с точным профилем
выбранной сети. Только после этого вызывается ограниченная по времени живая
проверка, предоставляемая будущим адаптером. Её контракт включает целевую сеть,
Ethernet и независимый watchdog; этот адаптер ещё не реализован.

После callback файл читается повторно и снова сравнивается; часы также читаются
повторно, чтобы медленная проверка не продлевала срок подтверждения. Ошибка,
исключение, смена кандидата или истёкший срок не снимают Pending. Подтверждённый
журнал перестаёт хранить резервный ключ. Авторизация билета пользователя остаётся
обязанностью будущего обработчика, эта функция не является публичным API.

Тесты проверяют старый файл вместо кандидата, чужой ID, отказ/исключение живой
проверки, замену файла во время callback, повтор commit и истечение срока прямо
во время проверки. Никаких реальных сетевых команд не выполняется. Последняя
гонка с изменением файла сторонним root-процессом после повторного чтения не
исключена: производственная схема должна запрещать конкурирующих писателей.
