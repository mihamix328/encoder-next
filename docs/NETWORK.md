# Сеть платы: состояние разработки

Проверенная пользователем конфигурация Orange Pi: Netplan + systemd-networkd,
служба netplan-wpa-wlan0; wpa_cli отвечает PONG. NetworkManager не используется.
Ethernet: 172.10.0.2/24; последний Wi-Fi IPv4: 10.0.0.59, выдан DHCP и может измениться.

В административном клиенте окно «Сеть платы» запрашивает IPv4-интерфейсы.
Кнопка Wi-Fi читает сохранённый список: BSSID, частота, уровень сигнала,
флаги защиты и SSID. Результаты могут быть устаревшими или неполными.
Кнопка не запускает новое сканирование и не меняет подключение.
Обычный клиент ещё не имеет сетевого раздела.

API `admin_network_status` и `admin_wifi_results` требуют административный токен.
Wi-Fi отключён по умолчанию (`wifi_read_enabled=false`). Сервер читает только
`wifi_snapshot_file=/run/encoder-network/wifi.txt`, а не управляющий сокет.
Отдельный Linux-сборщик encoder-wifi-collector отправляет только SCAN_RESULTS, без shell/sudo,
с ожиданием ответа до двух секунд и ограничением ответа 64 КиБ.
Ответ показывается как простой текст. Netplan-файлы и пароли не читаются.

Не включайте доступ на рабочей плате пока не проверена схема прав:
сам управляющий сокет wpa_supplicant не ограничивается чтением.
Не запускайте сервер от root, не выдавайте ему общий sudo и не делайте сокет
доступным всем. Код доступа к сокету больше не линкуется в основной сервер.

Подготовлены отдельные service/timer для сборщика. Он запускается локально
примерно каждые 30 секунд, не слушает сеть и не принимает аргументы.
В шаблоне он работает от root с пустым набором capabilities, группой encoder,
ограничением семейства сокетов AF_UNIX и доступом записи только к своему
runtime-каталогу (плюс изолированный временный каталог).
Это всё ещё привилегированный процесс: шаблоны требуют проверки на плате.
Сборщик и службы должны принадлежать root, без права изменения пользователем encoder.
Каталог /run/encoder-network имеет права root:encoder 0750, снимок — 0640:
сервер может читать, но не заменять файл. Основная служба дополнительно скрывает
/run/wpa_supplicant через InaccessiblePaths.

Сборщик атомарно заменяет снимок с отметкой времени. Сервер отклоняет файл
старше 90 секунд, дату из будущего, неверный формат и размер от 64 КиБ.
Отметка означает время чтения кэша, а не время радиосканирования.
При сбое сборщика старый снимок остаётся до истечения срока — это не новое сканирование.
Никаких установок или включения таймера на рабочей плате пока не выполнялось.

Смена сети, новый поиск, автоматический откат и обнаружение нового IP
ещё не реализованы. Действующая установка платы не обновлялась.

Windows TLS-тест проверяет отказ/отключённую функцию и чтение снимков:
отсутствующий, повреждённый, слишком большой, старый, будущий и корректный файл.
Это не проверка Linux-сборщика или его системных прав.
Для Linux подготовлен изолированный тест wifi-socket с поддельным UNIX-сокетом:
правильный ответ, FAIL, отсутствующий сокет, неверный путь и фиксированная команда.
Он включается опцией BUILD_UI_TESTS при сборке сервера и запускается через CTest.
12 сентября 2026 оба изолированных теста прошли на Orange Pi ARM64
под encoder-diag в отдельном каталоге /home/encoder-diag/encoder-check-ECm1Ll.
wifi-socket проверяет также слишком большой ответ и двухсекундный таймаут.
network-snapshot проверяет файлы снимков и чтение loopback-интерфейса.
Компиляция тестов и сборщика выполнена g++ с C++17 и
-Wall -Wextra -Wpedantic -Werror; предупреждений нет.
Сборщик только скомпилирован, с реальным Wi-Fi-сокетом не запускался.
Каталог /run/wpa_supplicant имеет права 0750 root:root;
encoder-diag доступа внутрь не имеет. Проверка службы и публикации снимка
под отдельными правами пока не выполнена. Рабочий сервер не заменялся,
сеть не менялась, systemd-службы не устанавливались.

Формат команды: [официальная документация wpa_supplicant](https://w1.fi/wpa_supplicant/devel/ctrl_iface_page.html).
