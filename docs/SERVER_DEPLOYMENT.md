# Подготовка новой установки Orange Pi

Это схема будущей установки, не команда обновления работающей платы.
Шаблон `deploy/encoder-server.service` пока не проверен на Linux/ARM.

## Размещение

- `/opt/encoder/bin/encoder-server` — собранный на Linux/ARM сервер.
- `/opt/encoder/bin/` — отдельные исполняемые файлы ГОСТ, когда они будут подготовлены.
- `/etc/encoder/server.conf` — конфигурация с абсолютными путями.
- `/etc/encoder/certs/` — сертификат и закрытый ключ; ключ доступен только службе.
- `/var/lib/encoder/` — данные службы: пользователи, ключи, хэши и журналы.
- Системный пользователь и группа `encoder` без интерактивного входа.

В конфигурации задайте `storage_dir=/var/lib/encoder` и абсолютные
`cert_file`, `key_file`, пути ГОСТ. Не копируйте Windows EXE на плату.
Установите собственный административный токен. Конфигурацию с токеном
и закрытый ключ не публикуйте в GitHub и не передавайте обычным клиентам.
Серверу нужны права чтения конфигурации/ключа и записи в каталог данных.

## Явный выбор конфигурации

```sh
/opt/encoder/bin/encoder-server --help
/opt/encoder/bin/encoder-server --config /etc/encoder/server.conf
```

При явно заданном неверном пути сервер завершится с ошибкой, без поиска
другого файла. Без `--config` прежний поиск конфигурации сохраняется.
Относительные пути внутри конфигурации считаются от рабочего каталога,
а не от расположения конфигурации — для службы используйте абсолютные.
Параметр `--config FILE` должен идти перед `--init-user USER PASSWORD`.
Последняя команда передаёт пароль аргументом процесса: используйте только
для начальной настройки в доверенной среде, затем управляйте пользователями
через административный клиент по TLS.

## Порядок переноса

1. Записать имя действующей службы и её конфигурацию. Согласовать окно остановки.
2. После остановки сохранить резервную копию конфигурации, сертификатов и всего
   `storage`, включая ключи. Без ключей старые файлы могут стать недоступны.
3. Собрать и проверить новую версию отдельно. Не заменять данные и бинарники
   действующей установки до проверки. Для параллельного теста нужны другие порты
   и отдельная копия данных; две службы не должны писать в одну базу.
4. Подготовить каталоги и права, перенести данные, установить шаблон службы.
   Проверить его через `systemd-analyze verify` на самой плате.
5. Запустить службу и проверить журнал, вход обычного пользователя,
   администрирование, ограничения и полный цикл на копии тестового файла.
6. Только после проверки включить автозапуск. Сохранить резервную копию
   и старые бинарники до успешной проверки совместимости файлов.

`ProtectHome=true` запрещает службе запуск ГОСТ из `/home/server/...`:
для этой схемы бинарники размещаются в `/opt/encoder/bin/`.
Шаблон не даёт серверу права менять сеть. Управление Wi-Fi потребует
отдельного ограниченного механизма, а не запуска всего сервера от root.
Возврат на старый сервер требует восстановления согласованной резервной копии:
старый формат не обеспечивает новые блокировки и права пользователей.
