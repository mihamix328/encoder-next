## Локальная проверка

Актуальные запускаемые сборки: `build/preview/client/encoder-client.exe`
и `build/preview/admin/encoder-admin.exe`.
Папки содержат локальную конфигурацию и не публикуются в Git.
Это сборки для проверки, не готовый проверенный релиз для другого ПК.

## Контрольная точка: упаковка

Свежие пробные комплекты: `build/portable/connection-preview/`.
Они включают новую форму подключения (выбор сертификата и сохранение настроек).
В комплекте нет сертификата конкретной платы и административных токенов.
Короткий запуск подтвердил только отсутствие немедленного завершения процессов;
это не проверка интерфейса, входа или шифрования.

Следующее продолжение:
1. Проверить новые комплекты вручную на текущем ПК, затем на чистом втором ПК.
2. Проверить вход с сертификатом платы, шифрование копии тестового файла и расшифрование.
3. Проверить пять пропусков смены пароля и обязательную смену на шестом закрытии.
4. Проверить сообщения об ошибках и кнопку доступности на втором ПК.
5. Продолжить аудит ролей, режимов ГОСТ и настройку сети по этапам выше.

## Автоматические проверки

Сборка с `-DBUILD_UI_TESTS=ON` добавляет четыре теста CTest:
локальное TCP-соединение/обмен/отказ и проверки интерфейса при 100%, 125%, 150%.
Проверяются высота списка, поиск алгоритмов, пять сохранённых пропусков
смены пароля и блокировка шестого закрытия. Настройки тестов изолированы.
Успешная смена пароля на реальном сервере и визуальная оценка отдельно.
Запуск: `ctest --test-dir build/windows-client -C Release --output-on-failure`.
Для Qt укажите QT_PLUGIN_PATH на каталог Qt6/plugins установленного vcpkg;
тесты используют платформенный плагин minimal.

Интеграционный тест сервера: `python server/tests/admin_protocol.py --server <путь-к-encoder-server> --openssl <путь-к-openssl>`.
Он создаёт временные сертификат, конфигурацию и базу пользователя, запускает
сервер только на loopback и завершает собственный процесс после теста.
Рабочая плата не используется. Запуск проверен на Windows; Linux/ARM ещё впереди.

## Точка продолжения

Новые клиентские архивы: `build/portable/encoder-network-preview/`.
Далее: модель пользователей (создание/сброс/блокировка/права), затем сеть платы.
Для установки и аппаратной проверки нужен доступ SSH к Orange Pi:
плата отвечает на 172.10.0.2, вход без пароля в текущей сессии не разрешён.
