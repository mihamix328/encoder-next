# Восстановление старого ГОСТ-формата

Старый gost.c шифрует Кузнечиком в ручном CBC. Он добавляет дополнение только
к неполному блоку. Поэтому последние байты кратного 16 файлу могут быть
ошибочно удалены старым дешифратором. Исправить эту неоднозначность без
дополнительной информации нельзя; угадывать длину небезопасно.

Добавлен режим decr.c `--raw-blocks`, который сохраняет все расшифрованные
блоки без удаления дополнения. Программа больше не печатает ключ в stdout.
Обычный трёхаргументный запуск сохраняет старое поведение для совместимости,
его нельзя считать исправленным производственным дешифратором.

`server/tools/recover_legacy_gost.py` проверяет полный результат и допустимый
вариант без дополнения по доверенной контрольной сумме исходного файла.
Только единственный совпавший вариант публикуется в новый файл с правами 0600.
Существующий выходной файл не заменяется. Публикация атомарная, через ссылку на
полностью записанный временный файл в том же каталоге. При остановке процесса
может остаться закрытый временный файл; это не означает успешного восстановления.

Использовать только в доверенном каталоге с доступом администратора. Это
инструмент миграции, а не новый формат шифрования или производственный API.
Не использовать контрольную сумму, полученную из недоверенного источника.
Контрольную сумму можно взять из соответствующей сохранённой серверной записи.
Алгоритм должен соответствовать фактическому алгоритму старой записи.
Историческая метка `streebog` в этом проекте обозначала SHA-256; инструмент
не называет SHA-256 Стрибогом и требует явно выбрать sha256 для такой записи.

```sh
gcc decr.c -o legacy-gost-recovery -lakrypt
python3 server/tools/recover_legacy_gost.py \
  --decoder ./legacy-gost-recovery \
  --ciphertext /trusted/file.bin --key /trusted/key.bin \
  --output /trusted/recovered.bin --algorithm sha256 \
  --trusted-digest HEX_FROM_TRUSTED_SERVER_RECORD
```

Не передавать сюда целый клиентский контейнер CIPHEATOR: инструмент ожидает
только внутренний шифротекст (IV + CBC-блоки) и чистый 32-байтовый ключ.
Автоматический разбор контейнера и серверной упаковки ключа этим этапом не добавлен.

Проверка на ARM64: 45 сочетаний длины и окончания файла; корректное восстановление,
отказ неверной контрольной сумме и отказ перезаписи. Настоящие пользовательские
файлы при испытании не использовались. Новое шифрование и исправление выбора
Магма/Кузнечик/режима требуют следующего этапа; рабочий сервер пока не заменён.
